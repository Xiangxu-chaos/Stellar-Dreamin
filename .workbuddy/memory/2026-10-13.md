### 关键设计决策（后续扩展必须遵守）

1. **词库加载走 `fetch(dataUrl)`，不用 JSON 动态 import**
   - 原因：浏览器不支持 import attributes，Node 也报 ERR_IMPORT_ATTRIBUTE_MISSING
   - 好处：浏览器与 Node 行为一致；`dataUrl` 天然是「换后端」的替换点
   - `wordBankService.BANK_REGISTRY` 已预留 cet4/kaoyan/ielts/toefl 槽位

2. **术语表命名用 `domainTerms`（不是 gameTerms）**，与领域无关的泛化命名。
   - `domainTerms`      = 专有名词 → 官方中文译名（用于命中判定 + 展示译名）
   - `domainVocabulary` = 领域常用英文词 → 中文（仅用于召回，**不当专有术语展示**）
   - `excludedTerms`    = 假阳性黑名单

3. **新增：`domainTermTiers` 术语权重分级**（本次加的架构改进）
   - 同样是专有术语，重要度不同：core(3) / mechanic(1.6) / relic|npc(0.5)
   - 排序：score 降序 → termWeight 降序 → 字母序
   - 目的：`ascension`(进阶)、`cleave`(顺劈斩) 排在 `abacus`(算盘) 之前
   - 加新领域时只需在配置里加 domainTermTiers，**不用改任何代码**
   - 解析函数 `resolveTermWeight(domain, term)`，支持 exact 列表 + pattern 正则

### 问题三：收藏数字更新但列表为空 —— 已修复（根因已定位）

→ 表现为「收藏夹数字更新了，但列表始终为空」。已用复现脚本验证：`keys=2 / list=0`。

**修复策略（双保险）**，改动文件 `src/services/dataService.js`：
1. 抽出**唯一读入口** `readFavoriteList()`；`getFavoriteKeys()` 与 `getFavorites()`
   都从这份「归一化后的列表」派生 —— **数量 ≡ 列表长度**，永久一致。
2. **自愈迁移**：读到脏数据时把能救活的记录改写成规范键 `domainId::word` 并异步回写；
   救不活的直接丢弃，不再污染计数。

## 【缺陷修复】收藏夹被「读操作写坏」（同日晚第三波）

用户症状：点收藏数字增加 → 一进收藏夹/复习收藏夹，数字立刻清零、内容清空、刷新也空。

### 根本原因（已复现，非读取失败，而是数据被覆盖）
**读路径上有写入副作用。** 上一轮为「顺手修脏数据」，在 `dataService.js` 的
`readFavoriteList()` 里加了自愈回写：

```js
if (dirty) writeRaw(KEYS.favorites, healed);   // ← 元凶
```

当整份 favorites 数据都无法归一化时，`healed = {}`，于是**一次普通读取就把
localStorage 写成 `{}`**，收藏全部被清空。时机完全吻合：页面进入收藏夹 →
`getFavoriteKeys()` / `getFavorites()` → 触发上述写入 → 数字清零、列表清空。

复现证据（修复前）：
```
修复前 localStorage = {"soul":1700000000000,"nail":1700000001000}
读取后 localStorage = {}            ← 纯读取把收藏清空了
```

### 修复内容
| 文件 | 变更 |
|---|---|
| `src/services/dataService.js` | **删除读路径上的一切写入**：`readFavoriteList()` 改为纯读取，脏数据「只忽略、不修改」。新增纯函数 `canonicalizeFavorites()`；把脏数据迁移**移到写路径**（`toggleFavorite` / `setFavorite` 的 `updateRaw` 队列内），只在用户主动操作时发生。`isFavorite()` 改为走归一化列表。`clearFavorites()` 补注释强调破坏性、只能由用户显式触发。 |
| `tools/verifyNoWriteOnRead.mjs` | **新增**：22 项断言。含「读取期间 setItem 调用次数 = 0」「localStorage 原始字符串逐字节不变」以及用户给的完整 6 步验收流程。 |
| `tools/verifyFix3FavoriteConsistency.mjs` | 场景 C 从「验证自愈回写」改为「验证读取不改动数据」「验证写路径迁移」。 |

## 续修（同日第三轮）：问题一 单词全大写 + 问题二 卡片翻不回来

### 问题一（杀戮尖塔 / 王者荣耀 单词显示全大写）—— 真根因：字体，不是 CSS 也不是数据
排查结论（三条都验证过）：
1. **不是 CSS `text-transform`**：`grep text-transform` 命中的 6 处全是品牌/眉标/领域副标题等装饰文本，
   `.wordcard__word` 本身**没有任何 `text-transform`**。
2. **不是数据大写**：四个材料文件 355 个键**全部小写**，0 个大写。
3. **真凶是 `theme.fontDisplay`**：`slay_the_spire`(L146) 与 `honor_of_kings`(L3435) 都用了
   **`'Cinzel'`**；Cinzel 是罗马石碑铭文风格字体，**字体文件里没有真正的小写字形**
   （全大写/小型大写）。浏览器遇到小写字母只能用大写字形替代 → `basement` 显示成 `BASEMENT`。
   `hollow_knight`(Cormorant Garamond) / `valorant`(Rajdhani) 有真实小写字形，所以正常。
   → 这就解释了「为什么只有这两个领域全大写」。

**修复**：凡是渲染「单词本身」的 CSS 类，一律把 `font-family` 从 `var(--font-display)`
改成 `var(--font-body)`，并加 `text-transform: lowercase` 双保险：
| 类 | 位置 | 用途 |
|---|---|---|
| `.wordcard__word` | components.css:1581 | 卡片正面单词 |
| `.flip__word` | components.css:672 | 详情/翻转卡大词 |
| `.detail__word` | components.css:983 | 详情弹窗标题词 |
| `.quiz__word` | components.css:1092 | 做题视图词 |
| `.quiz-card__prompt` | components.css:~1757 | 做题卡英译中题干 |

> 设计原则：**单词是给人读的正文，必须始终有真实小写字形**；`--font-display` 只留给
> 装饰性标题（empty__title / history-item__word / brand 等），不再承担单词渲染。

### 问题二（卡片翻面后无法翻回）—— 真根因：背面容器整体 stopPropagation
`wordCard.js` 的 `buildBack()` 第一行：
```js
const scroll = h('div.wordcard__backscroll', { onClick: (e) => e.stopPropagation() }); // 旧
```
整个背面容器阻止冒泡 → 点背面任何位置（空白/文字）都到不了卡片根节点的 `onClick`
→ 永远翻不回正面。
**修复**：背面容器不再整体 stopPropagation，改为 `const scroll = h('div.wordcard__backscroll');`。
背面三个按钮（放大查看/收藏/加入清单）各自的 `onClick` 里保留 `e.stopPropagation()`，
于是「点卡片翻面、点按钮不翻面」。

### 踩坑

- Node shim 的 `replaceChildren` **不会**把旧节点 `parentNode` 置空 →
  不能断言「querySelector 查不到旧 img」；应断言「容器 children 里没有 IMG」
  或「容器已标记 is-placeholder」。
- `h()` 把 `onError` 映射为 `addEventListener('error', ...)`，shim 的
  `dispatch('error')` 能正确命中；属性名 `referrerPolicy` 原样存（浏览器会
  规范化为小写），断言需大小写不敏感。
